Ranker-Pruned Fusion Phase 1 Results

Date: 2026-05-21

Scope

This note summarizes the first all-available run of QA/ranker-pruned fusion. The tested deployable pipeline rows use:

full_pipeline__qa_pruned_simple__{policy}

These are not ENSEMBLE rows. They are full-pipeline rows that apply QA/ranker pruning to the fusion proposal set and then run SIMPLE fusion.

Inputs

Ranked candidate tables:

hpc_results/soft_hybrid_probe/all_available_square_rect_full_image_local_support_pairwise_source_trainonly/features/

Paper-ready candidate inputs were resolved from each feature table's source_path, which points to the original fusion-ready parquet.

For a single fixed pruning policy, source_balanced_topk is the strongest setting with mean IoU 0.8654.

Interpretation

The first full pass supports the Phase 1 hypothesis: object-level QA/ranker pruning before SIMPLE fusion improves over the best fusion_only_* baseline on average. A single fixed policy, source_balanced_topk, improves the mean IoU from 0.8434 to 0.8654. Selecting the best QA-pruned SIMPLE policy per dataset reaches 0.8675, close to but still below the best external competitor average of 0.8712 and official silver truth average of 0.8819.

Dataset-level behavior is policy-dependent. source_balanced_topk is best for HSC and MuSC, top1_per_cluster is best for HeLa and GOWT1, and top2_per_cluster remains best for MSC.

Implementation Notes

Java/ImageJ fusion must be run outside the sandbox in this environment. The job file format and rank-slot input layout are supported by label-fusion-ng; the in-sandbox failure occurs while the Java TIFF reader opens staged images.

Interpretation:

  • Non-SIMPLE backends do not improve the best QA-pruned SIMPLE result overall.
  • BIC_WEIGHTED_VOTING and MAJORITY_FLAT tie in this sweep and are slightly below best-policy SIMPLE on average.
  • MuSC gains slightly from weighted/BIC or majority voting, but MSC regresses.
  • THRESHOLD_USER produced zero IoU on the single-slot top1_per_cluster datasets, so do not use it as evidence against QA pruning until that backend behavior is diagnosed.
