# Current Pipeline Handoff

This document is the shortest accurate description of what this repository is
currently doing, based on the maintained CLI code and the ablation runner.

It is intended as a handoff for a human reviewer or another agent who should
not need to read the whole repository line by line.

## Goal

The repository tries to build a segmentation result that beats either:

- the existing **silver truth**
- or the best individual **competitor**

using two learned components:

- a **QA regressor** that predicts how good one competitor's cell crop is
- an **ensemble / learned fusion model** that predicts a fused cell mask from
  multiple competitors

The maintained paper path is orchestrated by
[`scripts/run_ablation.py`](../scripts/run_ablation.py).

## Core Idea

For each ground-truth cell:

1. extract one crop per competitor
2. score or predict the quality of each crop
3. either:
   - keep the best crop (`qa_only`)
   - fuse all crops (`fusion_only`)
   - QA-filter then fuse (`full_pipeline`)
   - replace fusion with a learned ensemble (`ensemble_*`)
4. paste the chosen/fused/predicted crop back into the original full image
5. evaluate with the same sparse-GT, label-aware metric used for competitor and
   silver-truth baselines

## Canonical Evaluation Metric

The fair comparison metric is:

1. reconstruct a **labeled** full-image prediction
2. for each GT label, compare `(prediction == label)` vs `(gt == label)`
3. compute IoU/F1 per label
4. average across GT labels

This is the same metric used for:

- competitor baselines
- silver truth
- current final ablation evaluation

Important:

- crop-level Jaccard is still used internally for QA training and some fusion
  diagnostics
- the paper-comparable metric is the final **full-image label-aware IoU/F1**

## Main Data Objects

### 1. Whole-image dataframe

Built from synchronized datasets. One row corresponds to a GT image and carries
paths to competitor segmentations, GT, raw image, split assignment, and related
metadata.

Typical location:

- `data/dataframes/{dataset}/whole_image/*.parquet`

### 2. QA crop parquet

Built from the whole-image dataframe. Each row corresponds to **one competitor's
proposal for one logical cell**.

A logical cell is identified by:

- `campaign_number`
- `original_image_key`
- `label`

So one biological cell usually produces several QA rows, one per competitor.

Typical locations:

- `data/dataframes/{dataset}/qa_crops/base_sz{crop}_qa_dataset.parquet`
- `data/dataframes/{dataset}/qa_crops/fold-1_sz{crop}_qa_dataset.parquet`
- `data/dataframes/{dataset}/qa_crops/fold-2_sz{crop}_qa_dataset.parquet`

### 3. Stacked crop TIFF

Each QA crop row points to a `stacked_path` TIFF with shape `(4, H, W)`.

Channels:

- `0`: raw microscopy crop
- `1`: competitor segmentation crop
- `2`: GT mask crop
- `3`: tracking marker crop

Only channels `0,1` are used by the default QA CNN.

### 4. Ensemble databank

Built from QA crops. Each row corresponds to one training/eval example for the
ensemble model, with:

- `image_path`
- `gt_image`
- `label`
- `recon_crop_y_start/end`
- `recon_crop_x_start/end`
- `split`

Typical location:

- `data/ensemble_data/databanks/*.parquet`

## QA Network

### Purpose

Predict the quality of **one competitor crop for one cell**.

### Inputs

Source:

- `stacked_path` from the QA parquet

Default channels:

- `0`: raw crop
- `1`: competitor mask crop

So the QA model sees:

- what the cell looks like
- what one competitor predicted for that cell

### Label / target

Default target column:

- `jaccard_score`

This is generated by comparing the competitor crop mask against the GT crop mask
for that same cell.

The label is therefore:

- a **continuous regression target**
- crop-level IoU / Jaccard

### Output

The network outputs a single scalar:

- predicted crop quality

In downstream tables/parquets it is merged back as:

- `predicted_jaccard_index`

### Train / eval splits

The QA CNN reads the `split` column directly from the split-aware QA parquet:

- `train`
- `validation`
- `test`

### Artifacts

Training produces:

- model checkpoint / exported `.pt`
- Excel file with sheets `train`, `validation`, `test`

Each sheet contains:

- `cell_id`
- `Jaccard index`
- `Predicted Jaccard index`

### What QA is used for in the ablation pipeline

- `fusion_only`: ignore QA, use all candidates
- `qa_only`: keep the top-1 QA-scored candidate per logical cell
- `full_pipeline`: keep candidates above threshold; if none survive for a cell,
  keep the top-1 fallback

Current default threshold is controlled from `experiments/base.yaml`.

## Ensemble

### Purpose

Replace hand-designed Java voting fusion with a learned model that predicts a
fused mask for one cell crop.

### Main maintained dataset versions

The ablation path mainly uses:

- `C1`: normalized competitor overlap only
- `C2`: normalized competitor overlap + raw image

Interpretation:

- `C1` input is a single-channel "how many competitors agree here" image
- `C2` adds the raw microscopy crop as a second channel

### How the databank is built

For each logical cell:

1. collect all competitor crops for that cell
2. align them around the original crop center
3. sum / normalize their masks into a normalized overlap image
4. crop the GT mask for the same cell
5. optionally add the raw image channel
6. save a composed TIFF and a parquet row with reconstruction metadata

### Inputs

For `C1`:

- input: normalized overlap crop
- target: binary GT crop for that cell

For `C2`:

- input: normalized overlap crop + raw crop
- target: binary GT crop for that cell

### Output

The ensemble predicts a binary mask crop for that cell.

That prediction is then:

1. thresholded / binarized
2. pasted back into the full-image canvas using the stored reconstruction coords
3. scored with the same full-image label-aware metric as the baselines

### Evaluation levels

Two levels still appear in the code / MLflow:

- `cell_crop`: crop-level diagnostics
- `full_image_label`: final comparable metric

For paper-style comparison, only `full_image_label` matters.

## End-to-End Ablation Flow

### Phase A

- evaluate competitor baselines
- evaluate silver truth

These are direct full-image label-aware baseline scores.

### Phase B

- train QA CNN on split-aware QA crops
- evaluate QA regression quality
- evaluate threshold sweeps as QA diagnostics
- merge `predicted_jaccard_index` back into the QA parquet

### Phase C

Runs the actual methods being compared:

- `fusion_only`
- `qa_only`
- `full_pipeline`
- `ensemble_only`
- `ensemble_qa`
- `ensemble_qa_retrained`

Each branch produces final `full_image_label` evaluation outputs.

## Important Limits / Caveats

### Mixed split is not for paper claims

`mixed` is useful for development, not for fair paper reporting, because it can
bleed temporally correlated examples across train/test.

### Fold results can be asymmetric

Some folds have much less training data than others. Learned methods can be
much weaker on those folds.

### QA crop IoU is not the final metric

It is only:

- the QA supervision target
- and a diagnostic metric

The final comparison is always the reconstructed full-image label-aware score.

### Overlaps during reconstruction are resolved deterministically

When reconstructed cell masks overlap, the code resolves collisions with a
deterministic priority rule so the final labeled image is reproducible.
